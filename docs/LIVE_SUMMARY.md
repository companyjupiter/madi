## 왜 carry를 버렸나 — 실제 회의 재생으로 확인

옛 설계는 30초마다 **이전 요약(carry ≤400자) + 새 줄(≤700자)**로 불릿 3–6개를 다시 썼다.
출고 엔진(`translate-engine-4b`, `SOV_NSTEPS=512`)으로 앱 동작을 그대로 재생했다.

| 재생 (출고 4B) | 결과 |
|---|---|
| 40분 한국어 다화자 회의 | **영어 요약으로 뒤집힘**(한 번 영어로 나오면 carry가 굳힘) + 한자 혼입, 20분 이후 앞 5줄 고정, 핵심 사실 15개 중 2–3개, STT 잡음을 사실처럼 문장화 |
| 13분 한국어 과학 대담 | 후반만 남음(앞 절반 소실), 강연 내용을 **정반대로** 요약한 줄 1건 |
| 같은 구조, 예산 3배(carry 1200/창 2000/불릿 4–8) | 마지막 10분만 남음(2–3/15), 없는 고유명사 창작, in-flight **p50 4.5 s / max 5.9 s** |

원인은 예산이 아니라 구조다. **요약을 요약에서 다시 쓰면 매번 구체 정보가 깎인다** — 사후
요약 fold(800자 조각 반복 압축)와 같은 병. 불릿 수 고정은 길어지는 회의를 일반론으로
몰아넣는다.

## 현재 구조 — 노트를 추가만 한다

각 요청은 **새 줄만, 한 번** 읽고 **노트 0–1개**를 낸다. 앱은 그것을 **추가**만 하고 이전
노트를 다시 쓰지 않는다 → 드리프트가 구조적으로 불가능. 각 노트는 읽은 줄들의 id를 보존한다
(근거 추적, 재작업 분석 R5).

- 코어: `Transcript/LiveSummary.swift` (pure — 프롬프트·언어 가드·창·파서·중복·구간, SovereignCore+테스트)
- 스케줄러: `SessionController.tickLiveSummary` (라이브 레일 패턴 포크)
- 요청: `SummaryEngine.liveNote` → 태그 `live-summary` (SummaryReplySanitizer 경유)
- 표시: `UI/LiveSummaryPane.swift` — 5분 구간 헤더 + 노트, 최신 노트로 자동 스크롤.
  첫 노트가 도착하면 나타나고 녹음 종료와 함께 사라진다(사후 요약이 대체).

| 규칙 | 근거 (재생 측정) |
|---|---|
| 창: 새 줄을 **오래된 것부터** 1,000자까지, 나머지는 다음 틱 (`takeWindow`) | 옛 suffix 700은 적체 시 앞부분을 조용히 버림. 수 분 이상 굶은 레인만 최신으로 점프(`maxBacklogChars`) |
| 요청당 노트 1개, 새 줄 10줄 이상일 때 | 틱당 0–2개(78줄/40분) → 1개(53줄)에서 오히려 커버리지↑: 1분 분량에서 핵심을 고르니 잡담 조각을 덜 집는다 |
| 언어: 최근 300줄의 지배 문자로 정하고 **이름으로** 지시("반드시 한국어로만"), 출력 문자 검사로 거름 | "발언과 같은 언어로"는 영어 조각이 섞인 한국어 회의에서 영어로 뒤집힘. 핀 적용 후 문자 게이트 drop 0, 영어 클립은 영어로 정상 |
| '결정/합의'는 발언에서 명시한 경우만 | 프롬프트에 "(결정, 할 일…)" 목록을 두자 노트 12개가 하지 않은 결정을 주장 → 0 |
| 창에는 **모든 화자** 표시명(익명 "화자3" 포함), 노트에서 익명 라벨만 제거 | 이름 있는 화자만 라벨링하자 남의 발언이 그에게 귀속(21건) → 전원 라벨 후 14건, 남은 것은 실제 본인 발언 |
| "이미 기록한 항목" 문맥을 주지 않는다 | 문맥을 주면 모델이 되풀이 — 중복 20건 발생 |
| 구간(5분)은 **표시용**, LLM 정리 없음 | 구간 정리 단계가 쉼표 나열(한 줄에 7–8가지)의 발생원이자 가장 느린 요청(최대 3.2 s). 원본 노트는 78개 중 나열 1개 |
| 중복: 트라이그램 근접 또는 포함(≥0.8)이면 버림 | 앞 노트의 분할·메아리를 잡는다 |
| 거른 것: '없음', 6자 미만 조각, 140자 초과(발언 베끼기), 프롬프트 메아리("발언에서 가장 중요한 내용은…") | |

기각한 것: 노트↔원문 **어휘 대조 필터** — 기준 0.5에서 걸린 6줄 중 5줄이 올바른 의역이었고,
STT가 만든 무의미 문장은 원문에 그대로 있어 통과한다. 한국어 의역은 어휘로 판정 못 한다.

### 결과 (같은 재생, 출고 4B)

| | 40분 회의 커버리지 | 13분 대담 | in-flight p50 / max |
|---|---|---|---|
| 옛 carry | 2–3 / 15 (영어로 뒤집힘) | 5 / 12 (반대 내용 1) | 2.4 s / 4.3 s (대담 6.5 s) |
| **노트** | **14–15 / 15** | 9 / 12 | **1.2 s / 1.6 s** |

요청이 짧아져 **자막이 기다릴 수 있는 최악 시간도 줄었다**(브로커는 실행 중 요청을 선점하지 못한다).
STT 오인식 단어는 노트에도 남는다 — 요약 단계에서 고칠 수 없고, 노트마다 근거 줄 id가 있어
확인할 수 있다.

## 배선

`LiveFeatureWiring.liveSummary`는 **기본 OFF**. 실기기 라이브 세션에서 켬/끔 캡션 지연(ttft·NE)을
확인한 뒤 기본값을 바꾼다. 그 시험은 재빌드 없이:

```bash
defaults write com.companyjupiter.madi liveSummaryWired -bool YES
```

녹음 시작 시 읽는다. 끄려면 `defaults delete com.companyjupiter.madi liveSummaryWired`.
설정 → 실시간 요약 토글(`liveSummaryEnabled`, 기본 ON)은 배선이 켜졌을 때만 보인다.
