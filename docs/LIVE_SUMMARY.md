# 실시간 요약 (우측 요약 탭) — 설계·검증 정본 (2026-08-31)

사용자 요구: 라이브 전사가 적당히 쌓이면 핵심 요약을 우측 새 탭으로 보여줄 것.
템플릿은 자동 판단. **모든 상황에서 라이브 전사/번역 열화 금지.** 오래된 원문은
export만 온전하면 됨(라이브 요약 루프에 전량 재투입할 필요 없음).

상위 문서: `MEETING_INTELLIGENCE.md`(사후 요약), `SUMMARY_TEMPLATES.md`(템플릿 3종),
`BACKLOG.md` 2026-08-11 우측 패널 방향("AI 요약 계열은 탭 추가 방식, 라이브 중엔
실시간 가치 탭만 노출").

## 구조 — 롤링 carry

각 갱신은 **이전 요약(carry) + 마지막 갱신 이후의 새 줄만** 입력으로 받아 갱신된
불릿 리스트(3–6개)를 만든다. 오래된 원문은 carry로 접혀 라이브 루프에서 빠지고,
전체 전사는 TranscriptStore/자동저장에 그대로 남는다(export·사후 요약은 전문 사용).

- 코어: `Transcript/LiveSummary.swift` (pure — 프롬프트/캡/파서, SovereignCore+테스트)
- 스케줄러: `SessionController` (라이브레일 패턴 포크 — per-feature fork)
- 요청: `SummaryEngine.liveSummarize` → 태그 `live-summary`
- 표시: `UI/LiveSummaryPane.swift` — 녹음 중 explorer 자리, 첫 요약 도착 시
  슬라이드-인("양이 모이면 열리면서"), 녹음 종료와 함께 사라짐(정식 요약이 대체)
- 템플릿 자동: `session.summaryTemplate`(모드 유도)이 강조 너지만 제공 — 라이브
  출력은 템플릿과 무관하게 평면 불릿(섹션은 사후 요약의 것)

## 무열화 봉투 (핵심 제약의 이행)

| 층 | 메커니즘 |
|---|---|
| 하드웨어 게이트 | `liveRailCapable`(≥16GB)와 동일 — 이 게이트를 넘는 기기는 모델 티어 경계(12GB)상 **항상 4B** |
| 큐잉 게이트 (P11) | tick에서 `translateQueueDepth == 0 && translateBacklog == 0`일 때만 요청 생성 — 자막 밀림 중엔 시도 자체를 안 함 |
| 브로커 레인 | `.postSession`(10) — 레일(30)보다도 아래, 자막(80/100) 대기열을 절대 앞지르지 못함 |
| 브로커 2차 방어 | `eligibleIndex`: captionPressure>0이면 90s aging 전까지 부적격 |
| in-flight 상한 | 입력 캡(carry 400자 + 윈도 700자) + 짧은 불릿 출력 → **4B 실측 요청당 1.2–3.5s** = 자막이 겪을 수 있는 최악 블로킹(비선점 구간). 30s 주기·압력 0일 때만이라 실질 간섭 ~0 |
| in-flight 1개 | busy 플래그 + 2틱(60s) 언웨지 (레일과 동일) |
| 메모리 | 새 모델 없음 — 상주 DNA3 브로커 공유. 게이트 밖(8GB)에선 아무것도 안 함 |

## CLI 프로브 (2026-08-31, 확정 근거)

- **4B (게이트가 허용하는 유일한 티어)**: 형식 4/4 PASS(불릿 4–7), carry 롤링
  누적 검증(1라운드 결정 유지 + 3라운드 신규 반영), 요청당 총 소요 1.2–3.5s.
- **언어 A/B**: "전사와 같은 언어로"는 4B 영어 회의에서 한글 63자 누수
  ("리トライ" 혼종 포함) → **"반드시 발언과 같은 언어로만 답하세요(발언이 영어면
  영어로)"**로 교체, 누수 0자. 한국어 무회귀 확인.
- **2B**: 한국어 폭주(79불릿·8.9s) — 게이트 정당성의 실증. dev가
  `MADI_TRANSLATE_MODEL=2b`로 강제한 경우에도 표시는 sanitizer dedupe가 9줄로
  방어(블로킹 8.9s는 dev 책임 — 문서 기록만).

## 스케줄 파라미터

`LiveSummary.tickSeconds = 30`, `minNewLines = 6` — 레일(18s/3줄)보다 느긋하게.
핵심 요약은 액션보다 천천히 변한다. 갱신 실패/빈 응답 시 이전 요약 유지
(빈 패널·오염된 carry 둘 다 stale보다 나쁨).

## 알려진 한계 / 후속

- carry 롤링은 손실 압축 — 아주 긴 세션에서 초반 항목이 밀려날 수 있다(의도:
  "핵심" 요약이며, 전체는 사후 요약이 담당).
- 일시정지(paused) 중에는 tick이 멈춘다(phase == .recording 게이트).
- 설정 토글: 설정 → 실시간 요약 (기본 ON, 16GB 미만/모델 없음이면 비활성+안내).
