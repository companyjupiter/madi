# Sovereign Dashboard (scaffold)

Korea-friendly, information-dense live-transcription dashboard for the Sovereign
Whisper engine. This is a **scaffold** — a clean, typed skeleton meant to be
handed to a UI/UX engineer. The data model, theming, and component seams are in
place; the visual design is intentionally minimal so it can be elaborated.

## Run

```sh
cd web/dashboard
npm install
npm run dev        # http://127.0.0.1:5273  (predev copies ../fixtures → public/)
npm run build      # tsc + vite → dist/
```

No backend needed: the dashboard replays checked-in **fixtures** (`web/fixtures/*.events.jsonl`),
generated by the engine. Pick the demo source in the top-right dropdown.

## Data model — the engine event contract

The single source of truth is [`docs/EVENTS.md`](../../docs/EVENTS.md), mirrored
in [`src/types.ts`](src/types.ts). The engine (`metal/transcribe.zig`) emits a
versioned JSON-lines stream when run with `EVENTS_FILE=<path>`:

| event | carries |
|---|---|
| `meta` | model, language, sample rate, schema version |
| `word` | global `t0/t1`, softmax `conf` (0–1), `spk`, `text` |
| `seg` | per-30s-chunk text + perf (`tok_s/enc_ms/dec_ms`) + reserved `fallback/temp` |
| `spk_seg` | speaker-attributed run (`t0`, `spk`, `text`) |
| `diar` | final speaker count, silhouette, centroid separation, speech-window count |

`reduce()` in `types.ts` folds events → `SessionState`; `metrics.ts` derives KPIs.
Both are pure — trivially unit-testable and identical for fixture vs live data.

## Where to extend

```
src/
  types.ts          ← contract types + reducer (keep in sync with docs/EVENTS.md)
  metrics.ts        ← KPI / per-speaker / histogram derivations
  useEvents.ts      ← DATA SOURCE seam (fixture today → live SSE later)
  theme.css         ← design tokens (design/tokens.json) as CSS vars
  components/
    TopBar.tsx      ← session header + demo-source picker
    KpiRow.tsx      ← headline KPI tiles
    panels.tsx      ← 전사 / 화자 분석 / 품질 신호 / 성능
    charts.tsx      ← dependency-free SVG charts (Donut/Bars/Histogram/Timeline)
```

- **Theming**: edit `design/tokens.json` (Figma is the upstream); colors flow to
  both this dashboard (`theme.css`) and the macOS app (`Theme.swift`). Keep the
  speaker palette and low-confidence amber consistent across both products.
- **New panels**: add a component to `panels.tsx`, place it in `App.tsx`'s
  `gridTemplateAreas`. The grid is the layout contract.
- **Charts**: `charts.tsx` is hand-rolled SVG (no chart-lib lock-in). Swap for a
  chart library if you prefer — the panels pass plain data.

## Live bridge (next)

`useEvents.ts` is the seam. Today it `fetch`es a fixture and replays it. For a
live session, run the engine with `EVENTS_FILE` pointed at a fifo/socket, have a
tiny server stream new lines over **SSE/WebSocket**, and swap the fixture fetch
for an `EventSource`. The reducer and every panel stay unchanged — they already
consume events incrementally.

## Reserved fields (already in the model)

`seg.fallback` / `seg.temp` (temperature-fallback decoding) and `seg.bias_hits`
(term biasing) are emitted with defaults today so UI can bind to them before the
engine features land. When they go live, the corresponding panels (re-decode
badge, glossary) light up with zero data-model change.
